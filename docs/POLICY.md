# 현재 정책과 미확정 사항

이 문서는 확인된 구현·기존 명시 정책과 추가 결정이 필요한 항목을 구분한다.
현재 구현을 모두 승인된 정책으로 간주하지 않는다.

## 자료 접근 승인 서버 사실 조회 — 2단계 구현

`GET /api/admin/approvals/{id}/review-facts`는 관리자 계열의 `pending` 자료 접근
요청에만 허용하며 자기 요청 조회를 차단한다. 읽기 전용 반복 읽기 트랜잭션에서
요청·자료·업무 관계와 확인 가능한 감사 사건을 조회한다. 응답의 각 사실은 값,
출처 테이블·행 ID, 관측 시각, `unknown_reason`을 분리한다. 사유 원문, 사건 본문,
이름, 원시 감사 내용은 반환하지 않는다. 일반 사용자 API의 응답은 바꾸지 않는다.

신규 요청은 요청 감사 사건에 `reason_source=user_input/server_default`를 남긴다.
이전 기록은 같은 기본 문구를 사용자가 직접 입력했을 가능성을 배제할 수 없어
출처를 `unknown`으로 둔다. `want_download`는 요청 감사 사건의 승인·사용자·자료·
사유·시각 연결이 하나로 검증된 경우에만 제공한다. 현재 접근 평가는 재실행하지
않는다. 과거 `access_logs`에서 확인되는 점수와 최종 레벨은 당시 관측값으로만
제공하고, 별도 기록이 없는 점수 기반 기본 레벨·즉시 차단·현재 평가는
`unknown`이다. 과거 처리는 동일 요청자·자료의 이전 처리 승인 ID만 제공하며
유사성 및 결정 비교는 기준이 정해질 때까지 `비교 불가`다. 마이그레이션은 없다.

## AI 검토 지원 선행 설계 — 유형별 후속 범위

- AI의 역할은 승인 요청 근거의 출처 표시가 있는 요약, 필수 정보 누락·서술 모순
  표시, 유사한 과거 결정과의 차이 및 검토 의견 제안이다. 감사 이력에서는
  반복 접근·승인 편중·Break-Glass 사용 등 검토 후보를 근거 사건과 함께 묶고
  정책 변경 후보를 제안할 수 있다. 유사성이나 AI 의견을 승인 근거로 확정하지 않는다.
- 기존 서버가 4축 점수·즉시 차단·인증·예외 상태를 평가하고, 권한 있는 사람이
  승인·반려 및 사후 심사를 결정한다. AI는 접근 허용·차단, 승인 상태,
  담당 사건, Break-Glass, 신뢰도, 위험 점수, 정책값을 직접 변경하지 않는다.
  AI 호출 실패·출력 누락·오판은 기존 접근 경로를 허용으로 바꾸지 않는다.
- 정형 조건만으로 자동 처리할 수 있는 요청은 별도의 서버 정책 후보로 분리한다.
  대상 승인 유형, 허용·거부 조건, 만료·취소, 감사, 이의 제기 및 오탐 영향을
  합의하기 전에는 자동 승인 기능으로 간주하거나 구현하지 않는다.
- 검토자는 AI 의견과 정책 엔진의 사실값·감사 근거를 구분해 볼 수 있어야 한다.
  일반 사용자 응답에 내부 점수·감사 근거를 추가하지 않는다. AI 분석은
  접근 로그나 사용자 행동 횟수를 늘리지 않으며, 검토자 본인 관련 요청의
  자기 승인·자기 심사 차단을 우회하지 않는다.
- 현재 AI 정책 도전자의 합성 입력 경계는 실제 검토 자료 전송 허가가 아니다.
  실제 사용자·사건·요청 사유·감사 원문을 외부 모델에 보내는 범위,
  최소화·가명화 방법, 제공자 처리·보존 조건, AI 의견과 검토 결과의 보존 기간,
  검색·열람 권한을 별도로 결정한다. 결정 전 실제 자료 연동은 하지 않는다.
- 효과 평가는 승인 유형별 검토 시간과 재작업 감소뿐 아니라 부적절 승인,
  감사 누락, 오탐·미탐이 늘지 않는지도 함께 확인한다. 운영 데이터가 충분히
  검증되기 전에는 정책 변경 후보를 자동 적용하지 않는다.
- 기존 v2에서 구현한 합성 정책 도전자 전용 기능은 새 실무 목표와 맞지 않아
  제거할 예정이다. 제거 전까지는 아래 현행 입력·권한 경계를 유지하며,
  제거 시 실제 접근·승인 경로와 이미 기록된 감사 이력은 보존한다.

### 자료 접근 승인 AI 검토 — 3단계 구현 계약

`POST /api/admin/approvals/{id}/ai-review`는 관리자·부관리자·최고관리자만
명시적으로 호출한다. 서버는 2단계 `review-facts` 모듈에서 pending 상태,
요청자·자료 참조, 승인 필요 근거와 자기 처리 제한을 다시 검사한다. 읽기
트랜잭션에서 자료 접근 평가를 실행하지 않으며, 모델 호출 전에 닫는다.

모델 입력 allowlist는 요청 상태·시각·사유 출처·다운로드 희망, 자료 등급·
승인 필요 플래그·근거, 담당/부서/직무 관계, 마지막 관측 점수·최종 레벨과
시각, 현재 평가 미확인 사유, 과거 동일 요청자·자료의 처리 후보 상태·시각이다.
각 사실은 값·관측 시각·unknown 사유·호출별 근거 별칭으로만 전달한다.
과거 결정은 비교 불가로 표시한다. 요청 사유 원문, 사건 본문·증거·첨부·
사건번호·제목, 사용자 이름·연락처·원시 부서명·IP·위치, 세션·토큰·OTP,
감사 원문 및 내부 DB ID는 제외한다. 사유 원문을 보내지 않으므로
`reason_summary`는 `분석 불가: 요청 사유 원문 미전송`으로 제한한다.

모델 출력은 `reason_summary`, `missing_items[]`, `contradictions[]`,
`similar_decisions[]`, `review_opinion`, `uncertainties[]`, `evidence_refs[]`
만 허용한다. 의견은 보완 요청 검토·추가 확인·특이사항 없음에 대응하는
비구속 enum으로 제한한다. 항목마다 길이·개수·근거 별칭 또는 근거 없음
사유를 검사하며 과거 결정은 서버가 제공한 후보만 가리킬 수 있다.
모델이 추가 필드, 실행 가능한 승인/반려 값, 알 수 없거나 중복된 별칭을
보내면 실패한다. 검증된 별칭만 서버의 내부 근거 ID로 복원한다. 응답은
서버 `policy_facts`, `ai_review`, 서버/AI `uncertainties`, `evidence_ids`,
생성 시각과 모델 상태를 분리한다.

키 미설정·거부·시간 초과·네트워크/제공자 오류·출력 형식/근거 오류는
명시적 실패로 돌린다. 원문 입력·출력·프롬프트는 DB에 저장하지 않고,
감사에는 성공/실패, 승인 요청·검토자 ID, 오류 코드, 모델명만 기록한다.
AI 실패·미사용·반복 호출은 승인 상태·접근 로그·행동 점수·세션·정책을
변경하지 않는다. 실제 자료와 사유 원문의 외부 전송, 과거 결정의 유사성
기준, AI 의견의 보존 기간은 여전히 미확정이다. 3단계 코드는 구현됐으나
최종 테스트·격리 DB·화면 검증은 6단계 완료 후 수행한다.

## v2 AI 정책 도전자 — 제거 전 현행 구현 범위

- v1은 OpenAI API를 호출하지 않고 `OPENAI_API_KEY`를 사용하지 않는다.
  외부 AI 서비스 연결은 v2 정책 도전자 기능에만 도입한다.
- 관리자 또는 부관리자 권한을 서버에서 확인한 사용자만 합성 시나리오 실험을
  실행한다. 기존 관리자 감사 경로와 역할 정의를 재사용한다.
- AI는 접근 결정·점수·MFA·승인·Break-Glass·신뢰도·정책 임계값을 변경하지
  않는다. 모델 출력은 시뮬레이션 입력 후보와 설명이며 최종 판단의 근거가
  아니다. 실제 접근 API와 사용자 응답 범위는 유지한다.
- 외부 API에는 사전에 정의한 합성 역할·자료 등급·행동·환경 조건과 실험
  목표만 전달한다. 실제 사용자·사건 식별자, 자료 본문, 감사 로그 원문,
  비밀값은 전달하지 않는다. 초기 화면은 자유 입력을 받지 않는다.
- 모델 학습·파인튜닝과 실험 결과의 영구 저장을 하지 않는다. API 제공자의
  처리·보존 조건은 학습 여부와 별도로 확인하며, 실제 자료 전송은 별도
  정책 결정 전까지 허용하지 않는다.
- 시뮬레이션은 접근 로그 횟수, 세션 상태, 신뢰도, 위반 횟수, 승인 상태를
  바꾸지 않는다. 관리자 실행 사실은 기존 감사 경로에 남기되 합성 입력과
  결과를 실제 접근 사건으로 기록하지 않는다.
- 지원하지 않는 정책 분기나 필요한 상태를 확인할 수 없는 경우 결과를
  추정해 허용으로 표시하지 않는다. AI 호출 실패 시 기존 접근 결정은
  독립적으로 계속 동작하고 실험 API는 오류를 명시한다.
- AI 설명에는 실제 정책 엔진 결과와 가설·권고를 구분한다. 화면에는
  합성 시연이라는 표시와 지원한 정책 범위를 함께 제공한다.
- 3단계 관리자 API `POST /api/admin/policy-lab/challenges`는 기존 인증·세션 검사로
  `admin`, `superadmin`, `deputy_admin`만 허용한다. 고정 목표, 1~8개 시나리오,
  서버 합성 허용값의 부분집합만 받으며 알 수 없는 필드는 거부한다.
- 실행 성공·실패는 별도의 `POLICY_LAB_CHALLENGE` 감사 사건으로 기록한다.
  실행자, 고정 목표, 안전한 요청 개수, 상태, 오류 코드만 남긴다. 합성 입력·결과와
  AI 원문은 저장하지 않으며 실제 자료 접근·접근 결정 사건으로 기록하지 않는다.
- 합성 목표는 `boundary`, `immediate_block`만 지원한다.
  `approval_path`는 MFA·관리자 승인 상태를 재현하지 못하므로 외부 호출 전에
  명시적으로 거부한다. 시뮬레이터는 MFA·승인·Break-Glass·최종 접근 레벨을 평가하지 않는다.

확장 전 결정 필요: 실제 자료 전송 허용 범위와 보존 조건, 자유 입력 허용 여부,
실험 결과의 영구 보관 필요성. 이 결정 전에는 관련 기능을 구현하지 않는다.

## 이번 작업에서 유지하는 기준

- PostgreSQL 단일 DB, forward-only 마이그레이션, 기존 시드 페르소나 유지.
- 점수 기준 L1~L5 경계는 기본 25/50/75/90이며 민감도는 점수에 반영.
- confidence는 진단 정보이며 레벨을 변경하지 않는다 (`CONTRIBUTING.md`).
- 023 마이그레이션의 명시 정책: 강력범죄·조직범죄·국가안보 직무도
  야간 `ENV_NIGHT_TIME` 배율 1.0 적용. 기본값은 15점.
  이번 변경은 과거 016 시드의 감산을 기대하던 테스트만 이 기준에 맞춘다.
- 범용 multiplier 기능과 복수 범주 중 최솟값 선택 규칙은 유지.
- 담당 등록, 유효기간이 있는 자료 접근 승인, Break-Glass는 별도 권한.

## 미확정 / 별도 수정 필요

| 항목 | 현재 확인한 상태 | 필요한 결정·작업 |
| --- | --- | --- |
| 담당 등록 OTP | 화면과 서버의 승인 가능 상태가 다름 | OTP 필수 상태 전이 확정 및 공통 집행 |
| 응답 최소화 검증 | 사건 자료 API의 서버 응답과 화면 연결을 수정 | 격리 DB API 회귀·실제 화면 실증 대기 |
| 다운로드·복사 | 접근 점수 계산에서 현재 시도 가산 제외 | 누적 행동과 현재 동작 평가 의도 정리 |

위 항목은 배포 자동화 추가로 해결되지 않는다. 점수·본문 공개·인증 조건을
바꾸는 작업은 별도 정책 합의와 관련 테스트가 필요하다.

## 일반 사용자 상태 응답 범위

### 사건 자료 API (2026-10-04 확정)

- 일반 사용자와 관리자가 **일반 사건 API**를 호출하면 동일한 최소 응답을 받는다.
  내부 점수, 4축 내역, 기본·최종 레벨, 예외 규칙·사유, anomaly·policy 근거는
  반환하지 않는다. 관리자는 기존 권한 검증을 거친 감사 경로에서 근거를 확인한다.
- 사건 목록은 접근 평가 전 단계이므로 `id`, `title`, `is_assigned_case`만
  제공한다. 사건번호·설명·등급·자료유형·부서·승인 플래그는 목록에 포함하지
  않는다. 따라서 목록의 등급 필터도 제공하지 않는다.
- 상세 평가는 `request_id`, `status` (`ALLOW`/`VERIFY`/`DENY`),
  `external_message`, 허용 행동 `actions`, `resource`를 제공한다. 재인증·자료
  접근 승인 전과 거부 상태의 `resource`는 `id`, `title`만 포함한다. 열람이
  허용된 상태에서만 사건번호·등급·자료유형·부서·본문·워터마크를 제공한다.
  설명과 DB 내부 필드는 허용 후에도 제외한다. 허용 뒤에도 다운로드 권한은
  별도로 판단한다.
- `actions`는 열람·다운로드·복사·인쇄 허용 여부와 재인증·승인 요청·긴급
  접근 시도·긴급 접근 해제 안내만 포함한다. 긴급 접근 시도 안내는 실제
  발동 허가가 아니며 발동 API가 조건을 다시 검사한다.
- 상태 조회와 다운로드 평가 POST에는 `resource`를 포함하지 않는다. 파일
  다운로드는 서버가 새로 평가해 허용할 때만 본문 파일을 반환하며, 거부
  응답에는 공개 상태·행동 권한과 오류 코드만 포함한다. 상태 폴링은 접근
  행동 횟수를 올리지 않으며, 권한 하락 시 화면에 보관된 본문을 비운다.
- 비담당 사건 클릭 기록 API는 기록 여부만 반환한다. 클릭 횟수와 행동
  위험 가산값은 감사 기록과 서버 평가에만 사용한다.

- 담당 등록 요청의 생성·중복·내 요청 조회·OTP 확인 응답은 요청 ID,
  자료 ID, 처리 상태만 제공한다. 내 요청 조회에는 화면에 표시할 제목을 더한다.
  사건번호, 등급, 검토자, 사유 및 내부 처리 시각은 포함하지 않는다.
- 본인 Break-Glass 발동·활성 조회는 발동 ID, 범위, 자료 ID, 최소 등급,
  만료 시각, 상태만 제공한다. 정당화 사유와 세션·접속 정보는 감사 경로에 남긴다.
- 인증 전 로그인 승인 상태 폴링은 상태와 승인 시 만료 시각만 제공한다.
  요청 ID와 처리 시각은 포함하지 않는다.
- `/api/auth/me`는 화면의 사용자 식별·역할·표시 점수와 세션 잔여 시간만
  반환한다. 등록 기기·허용 위치·담당 사건과 세션 접속 이력은 포함하지 않는다.
- 관리자 감사·검토 API의 공개 범위와 인증·승인 조건은 이번 변경 대상이 아니다.

### 4단계 다른 승인 유형·감사 후보 구현 계약

관리자 전용 `GET /api/admin/reviews/{login|assignment|break_glass}/{id}/facts`는
읽기 전용 서버 스냅샷을, 같은 경로의 `POST .../ai-review`는 명시적 클릭에
따른 비구속적 AI 참고 의견을 반환한다. 검토자는 관리자 계열이어야 하고
요청자·발동자 자신은 AI 검토를 할 수 없다. 로그인 검토는 `pending`만,
담당 등록은 `pending_admin/otp_required/otp_verified`만, Break-Glass는
`expired/revoked/released`이면서 미심사인 발동만 조회한다. 담당 등록은
`reviewer_role`을 재검사하며 최고관리자는 전체를 본다. 기존 수동 로그인
승인의 단독 관리자 자기 승인 예외는 AI 검토에 적용하지 않는다.

모델 입력은 유형, 관측 시각, 호출 내 근거 별칭과 서버 확인 정형 값만이다.
로그인은 상태·요청 시각을 보내며 OTP·대기 요청 만료는 기록상 확인 불가
사유를 보낸다. 담당 등록은 상태·검토 역할·OTP 요구/검증 상태·현재
부서/직무 적합 여부를 보내며 요청 감사 사건이 없거나 중복이면 `unknown`이다.
Break-Glass는 상태·범위·최소 등급·발동/만료 시각·사용 감사 건수를 보내며
발동 감사가 없거나 중복이면 `unknown`, 사용 감사가 100건을 넘으면 건수도
`unknown`이다. 근거 별칭은 해당 요청 행, 현재 적합성에 사용한 사용자·자료
행 및 실제 연결을 확인한 감사 행만 가리킨다. 원시 사유, 사건 본문·제목·번호,
개인정보, IP·위치, 세션·토큰·OTP,
감사 원문은 전송하지 않는다.

AI 출력 계약은 `review_opinion`(추가 확인·보완 요청 검토·특이사항 없음),
`items[]`, `uncertainties[]`, `evidence_refs[]`다. 각 항목은 길이 1~300자의
문구, 최대 8개 근거 별칭, 근거가 없을 때 그 이유를 갖는다. 목록은 각각
최대 8개이며 서버가 필드·enum·길이·중복·별칭을 재검증한다. 응답은 서버
사실, AI 의견, 불확실성, 근거 ID를 분리한다. 원문 입력·출력·프롬프트는
저장하지 않고 검토 유형·대상·검토자·성공/실패·오류 코드·모델·시각만
감사한다. AI는 승인, 접근, 신뢰도, 위험 점수, 정책 상태를 변경하지 않는다.

`GET /api/admin/audit-candidates/emergency-access`는 실제 `BREAK_GLASS_USED`
감사 사건을 발동자와 발동 ID가 일치하는 경우에만 최근 100건까지 검토
후보로 반환한다. 각 후보는 감사 ID·관측 시각·발동 ID를 갖고 자동 제재나
판정을 하지 않는다. 세션을 넘는 반복 비담당 접근·승인 편중의 조회 기간,
추가 임계값, 동일인/승인자 집계 기준과 오탐 처리 기준은 **미확정**이다. 기간·임계값
합의 전에는 후보 판정 규칙을 추가하지 않는다. 이 조회의 100건 한도는
화면 표시량 제한이며 탐지 기간이나 위험 정책이 아니다.
`GET /api/admin/audit-candidates/repeated-unassigned`는 기존 비담당 클릭
감사 사건에서 같은 사용자·세션의 선행 사건이 확인될 때 두 감사 ID와 후행
관측 시각을 반환한다. 두 사건의 확인은 검토 후보 조건일 뿐 제재나 추가
점수 가산 기준이 아니다. 승인 편중의 조회 기간·집계 기준은 미확정이다.
